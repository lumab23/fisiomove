# B06: integração proposta para Luma

Registrar app.modules.notes.router.router em app/api/router.py e incluir o router;
ver b06-routing.patch. Importar/exportar Note de app.modules.notes.models no
registro app/db/models.py; b04-b06-models.patch reúne todos os modelos novos.
Os patches não foram aplicados aos arquivos compartilhados.

## Especificação da migração de observações

Criar revisão Alembic após a futura migração B04 (reconfirmar head antes da
integração). Criar notes conforme app/modules/notes/models.py: UUID id PK,
patient_id FK patients.id RESTRICT, author_id FK users.id RESTRICT, content TEXT
NOT NULL, visibility VARCHAR(30) NOT NULL, created_at e updated_at timestamps
com timezone NOT NULL. Índice ix_notes_patient_created(patient_id, created_at,
id). Checks nomeados via convenção Base: visibility somente patient_visible ou
professional_only; length(trim(content)) > 0. UUID/datas são gerados pela aplicação,
seguindo os modelos existentes, sem seed. Downgrade remove índice e tabela notes.
Validar upgrade/downgrade no PostgreSQL e comparar metadados antes de integrar.

A privacidade é aplicada ao SELECT e COUNT. Nenhum endpoint de notas é público.
A leitura usa get_current_user, a escrita require_role(PHYSIOTHERAPIST); ambos
verificam vínculo/identidade do paciente conforme o caso. A edição bloqueia a
linha da nota e exige autor e vínculo ativo. Nenhum histórico/sessão foi criado.

Para integrar as três tarefas de uma vez, usar **b04-b06-integration.patch**:
reúne os três routers e o registro de todos os modelos, com imports formatados.
É alternativa aos patches individuais, não deve ser aplicado junto deles.
Foi aplicado/validado somente em cópias temporárias dos arquivos; os arquivos
compartilhados do repositório continuam intocados. As migrações continuam sendo
especificações para a Luma criar na cadeia vigente.
